## 二、工作记录目录规则

从 2026-W33 起统一使用周目录：

```text
工作记录_YYYY-Www_MM-DD至MM-DD/
├── YYYY-MM-DD_工作记录.md
├── YYYY-MM-DD_工作记录.md
└── 同周其他专题或证据文件
```

执行规则：

1. 自然周按周一至周日计算。
2. 同一周只建立一个工作记录目录；每天需要归档时，在该目录新增 `YYYY-MM-DD_工作记录.md`。
3. 不再新增 `工作记录_YYYY-MM-DD/` 单日目录。
4. 跨周才建立新的周目录。
5. 旧单日目录属于历史 Source Layer，保留原路径，不为格式统一而批量移动。
6. 工作记录只写可核对事实、签收决策、风险和下一步；长期有效结论继续沉淀到对应主笔记。

## 三、根目录规则

根目录长期保留：

- `AGENTS.md`：Agent 与知识维护规则。
- `文档规则与索引.md`：Vault 导航与工作记录制度。
- `重要变更与PR基线记录.md`：当前开发真源和切换历史。
- `W33_PR合并进展表_2026-08-13.md`：当前唯一 PR 执行入口；只维护遗留收口和已选择的 Roadmap 能力线。
- `NextGen_Beauty_产品需求池.md`：跨 Community / Studio 的长期需求真源。
- `NextGen_Beauty_Studio_V7.2_General_PRD_Brief_2026-08-12.md`：v0.7.2 产品范围与权威 Brief。
- `Community_V7.2_Roadmap_2026-08-12.md` 与 `Studio_Editor_V7.2_Roadmap_2026-08-12.md`：分域路线图。
- `README_V7_系统架构总览与权威文档索引.md`：v0.7.2 架构与领域文档第一入口；文件名保持稳定。

- 当前产品/架构基线唯一写作 `v0.7.2`，active 文档 frontmatter 使用 `version: v0.7.2`。
- `EditorDocV7 / schemaVersion: 7`、`nextgen.beauty.device.v1`、Scan/Manufacturing/Artifact/Vendor 合同各自独立版本化。
- 文件名中的 `V7`/`V7.2`、既有 `V7-* / COMM-V7.1-* / STUDIO-V7.1-*` PR ID 与历史日志不机械改名。
- 三份 V7.1 PR 表已归档到 `归档/PR执行表_2026-W33前/`，是历史 execution ledger；当前 PR 状态只更新 [[W33_PR合并进展表_2026-08-13]]。
- Source Layer 和 superseded 文件保留当时称谓，不因当前基线升级而重写历史事实。

## 六、更新检查

新增或修改重要文档后至少检查：

- 是否已有同主题主笔记。
- 是否区分事实、判断、规划与待验证内容。
- 是否链接上位索引与相关决策。
- 是否更新 `updated`、状态和替代关系。
- 是否把本地提交误写成已 push、已部署或生产可用。
- 是否把 SVG、Three.js 或模拟测试误写成制造证明。
